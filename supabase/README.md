# Haven Mattresses Kenya - Supabase Production Database Documentation

This document explains the production Supabase PostgreSQL architecture, migration steps, security rules, authentication flows, and integration guidelines.

---

## 1. How to Run the Migration

1. Open your [Supabase Project Dashboard](https://supabase.com/dashboard).
2. Select your project (e.g. `hepedzbbmrdsslvxiobv`).
3. In the left navigation sidebar, click on **SQL Editor**.
4. Open the migration file: `supabase/migrations/001_initial_schema.sql` (or copy it directly from the Admin Dashboard under **Settings → View SQL Schema**).
5. Paste the entire SQL script into the SQL Editor and click **Run**.
6. The query will execute idempotently, creating all extensions, tables, constraints, functions, triggers, Row Level Security (RLS) policies, and storage buckets.

## 2. Tables Created

| Table Name | Description | Key Relationships / Constraints |
| :--- | :--- | :--- |
| `profiles` | User profiles synced with Supabase Auth | `id` references `auth.users(id)` ON DELETE CASCADE. Roles: `customer`, `staff`, `admin`, `driver`. |
| `addresses` | Customer delivery addresses | References `profiles(id)` ON DELETE CASCADE. |
| `categories` | Mattress & bedding categories | Unique `slug`, display order, active status flag. |
| `products` | Product catalog (Mattresses, Pillows, Protectors) | References `categories(id)` ON DELETE SET NULL. Unique `slug` and `sku`. |
| `product_variants` | Mattress dimensions, firmness, selling price, and supplier costs | References `products(id)` ON DELETE CASCADE. `supplier_cost` hidden from customers via RLS. |
| `product_images` | High-resolution photography for variants/models | References `products(id)` ON DELETE CASCADE. |
| `suppliers` | Factory suppliers & manufacturers (e.g., Silentnight, Dr. Mattress) | Admin/Staff access only. |
| `supplier_products` | B2B supplier price matrix and lead times | Unique `(supplier_id, product_variant_id)`. |
| `wishlists` & `wishlist_items` | Customer saved items | Unique per user, duplicate prevention on items. |
| `carts` & `cart_items` | Session and authenticated shopping carts | Foreign keys to `product_variants`, quantity check constraints. |
| `delivery_zones` | Kenya counties, towns, and delivery fee rules | County-based fee calculation and ETA lookup. |
| `orders` | Customer purchases, delivery address, status lifecycle | `order_number` generated by database sequence (`ORD-YYYY-000001`). `user_id` ON DELETE SET NULL to preserve history. |
| `order_items` | Immutable price snapshots of ordered items | Stores frozen `unit_price` and `supplier_cost` snapshots. |
| `payments` | Safaricom M-Pesa Daraja and payment records | Unique `provider_transaction_id` prevents duplicate charges/receipts. |
| `order_status_history` | Audit trail of every lifecycle status change | Records timestamp and `changed_by` admin/staff UUID. |
| `drivers` & `driver_assignments` | Logistics drivers and route fulfillment | Unique 1-to-1 link with driver profile. Driver can only see and update their assigned orders. |
| `reviews` | Customer ratings & reviews | Check constraint `1 <= rating <= 5`. Verified purchase enforcement via RLS. |
| `coupons` & `coupon_usages` | Promotional discounts & per-user usage tracking | Unique codes, minimum order validation, start/end dates. |
| `notifications` | In-app alerts and customer updates | Real-time notifications per user profile. |
| `admin_activity_logs` | Immutable admin audit trail | Logs admin actions, entity mutations, IP addresses, and JSON payloads. |
| `business_settings` | Single-row store metadata & M-Pesa config | Editable exclusively by verified Administrators. |
| `support_tickets` & `support_messages` | Customer service ticketing | Threaded conversation between customer and support staff. |

## 3. How Authentication Works

- **Supabase Auth (`auth.users`)**: Handles signup, signin, password hashing, and token issuing. Passwords are never stored in public tables.
- **Automatic Profile Trigger (`handle_new_user`)**: When any user signs up, a PostgreSQL trigger fires on `auth.users` and automatically creates a row in `public.profiles`.
- **Enforced Default Role**: The signup trigger strictly assigns `role = 'customer'` and `account_status = 'active'`. A user cannot self-assign the `admin` role during signup.

---

## 4. Roles & Permissions

1. **`customer`**:
   - Read active products, categories, approved reviews, and delivery zones.
   - Manage own profile, saved addresses, wishlist, and cart.
   - Place orders, view own order history, and submit reviews for delivered purchases.
2. **`staff`**:
   - View customer orders, update order status, review payments, and dispatch orders.
   - Respond to support tickets.
3. **`driver`**:
   - View only their assigned deliveries via `driver_assignments`.
   - Update delivery status (`picked_up`, `out_for_delivery`, `delivered`).
4. **`admin`**:
   - Full read/write access to all tables, products, pricing, suppliers, supplier costs, settings, coupons, and activity logs.

## 5. How to Create the First Admin Securely

1. Have the user sign up normally through Supabase Auth (or in the app).
2. Open the **SQL Editor** in Supabase.
3. Run the following command with the user's email:

```sql
UPDATE public.profiles
SET role = 'admin'
WHERE email = 'your-email@havenmattresses.co.ke';
```

## 6. How Row Level Security (RLS) Works

- RLS is enabled on **all 24 application tables**.
- **Helper Functions**:
  - `public.is_admin()` and `public.is_admin_or_staff()` run in `SECURITY DEFINER` mode to perform fast, recursion-free role checks.
- **Supplier Cost Protection**:
  - Regular customers cannot query `suppliers` or `supplier_products`.
  - Customer-safe database views (`customer_product_variants` and `customer_order_items`) omit `supplier_cost`.
- **Review Integrity**:
  - Only authenticated customers with a completed order (`order_status = 'delivered'`) containing the product are permitted to insert reviews.

## 8. Client vs. Server Responsibilities

### Operations Allowed on Frontend (Supabase Client SDK):
- Querying active products, categories, variants, and product images.
- Reading approved reviews.
- Managing user's own cart, wishlist, notifications, and profile.
- Uploading customer avatars to the `avatars` storage bucket.

### Operations That MUST Go Through Server API / Edge Functions:
- **M-Pesa STK Push & Daraja Webhook Validation**: Never trust frontend payment flags; update `payment_status` and `order_status` only upon receiving a validated Safaricom Daraja callback.
- **Price Calculation & Checkout**: Server re-validates current product prices and applies coupon math before creating the finalized `orders` and `order_items` record.
- **Supplier Cost & Margin Analytics**: Aggregated in backend routes to protect factory pricing.
